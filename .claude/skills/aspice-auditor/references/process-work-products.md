# 프로세스 영역 → 대표 산출물 (방향 설정용 참고자료)

CL2 기준으로 자주 평가되는 각 A-SPICE 4.1 프로세스 영역이 무엇을 산출하도록 기대되는지 실무자 수준으로 요약한 자료입니다. 방향을 잡기 위한 참고 목적일 뿐이며, 인증 등급의 엄밀함이 필요할 때 공식 프로세스 평가 모델(PAM)을 대체하지 않습니다. 아래 프로세스 영역은 CL2에서 가장 흔히 평가되는 "VDA 스코프" 위주입니다.

## 시스템 엔지니어링 (SYS)

- **SYS.1 요구사항 도출(Requirements Elicitation)** — 이해관계자 요구사항 기록, 도출/의사소통 기록.
- **SYS.2 시스템 요구사항 분석(System Requirements Analysis)** — 속성(우선순위, 안전성/치명도, 검증 기준)을 포함한 시스템 요구사항 명세, 이해관계자 요구사항과의 양방향 추적성.
- **SYS.3 시스템 아키텍처 설계(System Architectural Design)** — 시스템 아키텍처 기술서, 인터페이스 요구사항, 시스템 요구사항과의 추적성.
- **SYS.4 시스템 통합 및 통합 테스트(System Integration and Integration Test)** — 통합 전략, 통합 테스트 명세, 통합 테스트 결과, 아키텍처/인터페이스와의 추적성.
- **SYS.5 시스템 검증 테스트(System Qualification Test)** — 검증 테스트 전략, 테스트 명세, 테스트 결과, 시스템 요구사항과의 추적성.

## 소프트웨어 엔지니어링 (SWE)

- **SWE.1 소프트웨어 요구사항 분석(Software Requirements Analysis)** — 소프트웨어 요구사항 명세, 시스템 요구사항(SYS 레이어가 없다면 이해관계자 요구사항)과의 추적성.
- **SWE.2 소프트웨어 아키텍처 설계(Software Architectural Design)** — 소프트웨어 아키텍처, 동적 동작 기술, 자원 사용 목표, 소프트웨어 요구사항과의 추적성.
- **SWE.3 소프트웨어 상세설계 및 단위 구현(Software Detailed Design and Unit Construction)** — 상세설계, 소스코드, 아키텍처와의 추적성.
- **SWE.4 소프트웨어 단위 검증(Software Unit Verification)** — 단위 검증 전략, 단위 테스트 명세/결과, 정적분석 결과, 상세설계와의 추적성.
- **SWE.5 소프트웨어 통합 및 통합 테스트(Software Integration and Integration Test)** — 통합 전략, 통합 테스트 명세/결과, 아키텍처와의 추적성.
- **SWE.6 소프트웨어 검증 테스트(Software Qualification Test)** — 검증 테스트 전략, 테스트 명세/결과, 소프트웨어 요구사항과의 추적성.

## 지원 프로세스 (SUP)

- **SUP.1 품질 보증(Quality Assurance)** — 품질보증 계획, 감사/리뷰 기록, 부적합 기록, 에스컬레이션 기록.
- **SUP.8 형상관리(Configuration Management)** — 형상관리 계획, 형상항목 목록, 베이스라인 기록, 변경/버전 이력.
- **SUP.9 문제 해결 관리(Problem Resolution Management)** — 문제 기록 로그, 근본원인 분석, 해결/검증 상태.
- **SUP.10 변경 요청 관리(Change Request Management)** — 변경 요청 로그, 영향 분석, 승인/반려 기록, 구현 상태.

## 관리 (MAN)

- **MAN.3 프로젝트 관리(Project Management)** — 프로젝트 계획(범위, 일정, 자원), 리스크 관리 기록, 이해관계자 참여 계획, 진척/상태 보고서, 리뷰/의사결정 기록.

## 획득 (ACQ)

- **ACQ.4 공급자 모니터링(Supplier Monitoring)** — 공급자 협약서, 모니터링 계획, 리뷰/상태 기록, 공급자 이탈에 대한 에스컬레이션 기록.

## 감사원을 위한 참고 사항

- 프로세스 영역의 CL1 근거란 "기본 관행에 따른 산출물이 실제로 존재하고 기대 내용을 담고 있다"는 것입니다. CL2는 새로운 산출물 *종류*를 추가하지 않습니다 — 동일한 산출물의 *생성과 관리*가 계획, 모니터링, 통제되고 있다는 근거를 추가로 요구합니다(`cl2-checklist.md` 참고).
- 위 목록에 없는 프로세스 영역이 요청되면, 추측하지 말고 그 사실을 알리거나(또는 조사한 뒤) 예상 산출물을 확인해야 합니다.
