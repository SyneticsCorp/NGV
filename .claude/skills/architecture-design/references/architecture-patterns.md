# 후보 아키텍처 패턴 카탈로그

1단계(후보 제안)에서 프로젝트 특성에 맞는 2~4개를 선정하는 데 사용합니다. 자동차 도메인(ISO 26262/A-SPICE)에서 흔히 쓰이는 패턴을 포함합니다. 목록에 없는 패턴이 더 적합하다고 판단되면 지어내지 말고 왜 그런지 근거를 들어 별도로 제안하세요.

사용자가 후보 중 하나를 선택하면, 선택된 패턴과 선정 사유를 `TPL-SWE2-001` 2장(아키텍처 설계 원칙)에 요약하고, 그 패턴에 따른 아키텍처 요소 분해를 3장(논리 아키텍처)에 기술합니다(`template-policy.md`).

## 범용 패턴

- **레이어드 아키텍처(Layered Architecture)** — 상위 계층이 하위 계층에만 의존하는 수직 분할. 결합도를 낮추기 쉽고 이해하기 쉬우나, 계층을 관통하는 기능(횡단 관심사)이 있으면 응집도가 흐트러지기 쉽습니다.
- **헥사고날(포트&어댑터, Hexagonal/Ports & Adapters)** — 핵심 로직을 인터페이스(포트)로 감싸고, 외부 연동은 어댑터로 분리. 변경 유연성과 테스트 용이성이 높고, 인터페이스 기반 통신을 자연스럽게 강제합니다. 요청된 "인터페이스로만 통신" 요구사항과 특히 궁합이 좋습니다.
- **컴포넌트 기반 아키텍처(Component-Based Architecture)** — 명시적 인터페이스를 가진 재사용 가능한 컴포넌트 조립. 응집도/결합도 관리가 직접적이며, A-SPICE의 컴포넌트/인터페이스 중심 기대사항과 잘 맞습니다.
- **이벤트 기반 아키텍처(Event-Driven Architecture)** — 컴포넌트가 이벤트 발행/구독으로 느슨하게 결합. 확장성과 변경 유연성이 높으나, 이벤트 흐름이 복잡해지면 추적성·디버깅 난이도가 올라갈 수 있어 안전 필수 경로에는 신중한 적용이 필요합니다.
- **파이프-필터(Pipe-and-Filter)** — 데이터가 일련의 처리 단계를 순차 통과. 신호처리/데이터 파이프라인 성격의 기능에 적합하고 각 필터의 응집도가 높습니다.
- **클라이언트-서버(Client-Server)** — 서비스 제공자와 소비자 분리. 원격/분산 구성 요소가 있는 시스템에 적합합니다.

## 자동차 도메인 특화 패턴

- **AUTOSAR형 계층 구조(Application / RTE / BSW / MCAL)** — Application 계층은 하드웨어에 독립적으로 작성되고, RTE(Runtime Environment)가 컴포넌트 간 통신을 인터페이스로 중개하며, BSW(Basic Software)·MCAL이 하드웨어 접근을 캡슐화합니다. 인터페이스 기반 통신 강제, 변경 유연성(하드웨어 교체 시 Application 영향 최소화)에 특히 적합한 자동차 SW 표준 구조입니다.
- **안전 아키텍처 패턴(모니터-액추에이터, 이중화/투표)** — 기능을 수행하는 요소(액추에이터)와 그 동작을 독립적으로 감시하는 요소(모니터)를 분리하거나, 동일 기능을 이중/삼중으로 구성해 상호 비교(1oo2, 2oo3 등)합니다. 높은 ASIL 요구사항이 있는 기능에서 안전 메커니즘을 아키텍처 수준에서 보장하기 위해 다른 구조 패턴과 함께(하이브리드로) 적용되는 경우가 많습니다.
- **프리덤 프롬 인터피어런스(간섭으로부터의 자유) 분할** — 서로 다른 ASIL을 가진 요소들을 공간적/시간적으로 분리(파티셔닝)해, 낮은 ASIL 요소의 결함이 높은 ASIL 요소에 영향을 주지 못하게 합니다. 하나의 구조라기보다 다른 패턴에 얹는 제약 조건으로, 안전 관련 요구사항이 있으면 후보 비교 시 항상 함께 고려하세요.

## 후보 비교 시 평가 항목 (1단계 제안에 포함)

각 후보에 대해 다음을 표로 정리해 제시하세요.

| 항목 | 설명 |
| --- | --- |
| 적합성 | 이 프로젝트의 기능/비기능 요구사항, ASIL, 제약과 얼마나 맞는가 |
| 응집도/결합도 | 이 구조를 따를 때 자연스럽게 얻어지는 응집도/결합도 수준 |
| 변경 유연성 | 요구사항 변경 시 영향 범위가 얼마나 국소화되는가 |
| SOLID 정합성 | 이 구조가 SOLID 원칙 적용을 쉽게/어렵게 만드는 지점 |
| 인터페이스/통합 | 인터페이스 경계가 자연스러운지, 통합 순서를 정하기 쉬운지 |
| 표준 정렬 | ISO 26262 Part 6 안전 아키텍처 원칙, A-SPICE SYS.3/SWE.2와의 정합성 |
| 리스크/단점 | 이 구조를 택했을 때의 트레이드오프 |
