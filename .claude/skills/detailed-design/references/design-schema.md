# 작업용 상세설계 스키마 (TPL-SWE3-001 대응)

TPL-SWE3-001은 장/절 구조와 서술형 작성 안내만 제공하고, 고정 표를 강제하지 않습니다(문서 메타/변경 이력/승인 상태 표 3개 제외). 이 문서는 각 장 안에서 상세설계를 일관되게 기술하기 위한 작업용 필드 스키마입니다.

## ID 체계

- 구현 단위(모듈/클래스): `IU-<일련번호>` (예: `IU-0007`). `architecture-design`의 `ARC-NNNN`, `requirements-analysis`의 `SWR-NNNN`과 나란히 쓰이는 접두사 체계입니다.
- 함수/오퍼레이션: 별도 ID를 만들지 않고 `IU-NNNN.함수명`으로 참조합니다(예: `IU-0007.calculate_offset`).
- 프로젝트에 이미 다른 접두사가 쓰이고 있다면 새로 만들지 말고 기존 체계를 따르세요.
- 일련번호는 4자리, 0으로 채웁니다. ID는 재사용하지 않습니다.

## 2장 — 모듈 분해

| 필드 | 설명 |
| --- | --- |
| 구현 단위 ID | `IU-NNNN` |
| 책임 | 이 단위가 담당하는 기능(하나의 명확한 책임 — `architecture-design`의 응집도 기준과 동일 원칙) |
| 소스 위치 | 파일/모듈 경로 |
| 대응 아키텍처 요소 | `ARC-NNNN` (`architecture-design`의 논리 아키텍처 요소) |

## 3장 — 상세 호출관계

호출 순서, 의존 방향(어느 단위가 어느 단위를 호출하는가), 주요 데이터 흐름을 기술합니다. `detailed-design-diagrams.md`의 다이어그램과 반드시 일치해야 합니다.

## 4장 — 공통 자료형

각 자료형: `이름`, `구조/필드`, `단위/범위`, `불변조건(invariant)`, `직렬화 규칙(해당 시)`.

## 5장 — 핵심 함수 계약

| 필드 | 설명 |
| --- | --- |
| 함수 ID | `IU-NNNN.함수명` |
| 입력 | 파라미터, 타입, 범위 |
| 출력 | 반환값, 타입, 범위 |
| 사전조건 | 호출 전 보장되어야 할 조건 |
| 사후조건 | 호출 후 보장되는 결과 |
| 부작용 | 상태 변경, I/O 등 |
| 예외/오류 | 실패 시 반환값/예외와 호출 측 처리 기대사항 |
| 시간 제약 | 실행시간 상한 등(해당 시) |

모호한 계약(예: "적절히 처리한다")은 허용하지 않습니다 — `requirements-analysis`의 EARS 원칙과 동일하게, 계약도 검증 가능한 문장으로 작성합니다.

## 6장 — 핵심 알고리즘

처리 순서, 판단 조건, 경계값과 계산 근거를 의사코드 또는 흐름도(Mermaid `flowchart`)로 기술합니다. 근거 없는 경계값(매직 넘버)을 쓰지 말고, 어느 요구사항/제약에서 그 값이 나왔는지 명시합니다.

## 7장 — 정책 의사결정표

입력 조건 조합별 기대 동작을 결정표(decision table) 형식으로 작성합니다.

```markdown
| 조건1 | 조건2 | 우선순위 | 기대 동작 |
| --- | --- | --- | --- |
```

조건 조합이 서로 충돌할 수 있는 경우, 충돌 해결 규칙(우선순위)을 명시적으로 적습니다 — 암묵적으로 "먼저 적힌 것이 우선"인 방식으로 남겨두지 않습니다.

## 8장 — 상태전이 상세

상태 저장 위치, 전이 함수, 트리거 이벤트, 가드 조건, 타이머, 초기화 동작을 기술합니다. `detailed-design-diagrams.md`의 `stateDiagram-v2`로 함께 표현합니다.

## 9장 — Web 및 API 상세 (해당 시에만 작성)

엔드포인트, 요청/응답 구조, 입력 검증 규칙, 오류 코드, 세션/보안 경계를 기술합니다. Web/API 컴포넌트가 없으면 "해당 없음"으로 명시합니다.

## 10장 — 오류와 방어 동작

유효하지 않은 입력, 예외, 자원 실패(메모리/디스크/네트워크 등) 각각에 대해 검출 방법, 처리 방법, 기록(로그) 방법, 복구 방법을 기술합니다. 안전 관련 단위(대응 요구사항이 `SWR-NNNN`의 4.2 안전관련SW요구사항)라면 `iso26262-aspice-alignment.md`의 안전 메커니즘과 연결합니다.

## 11장 — 코딩 및 검증 규칙

`coding-and-verification-rules.md`를 그대로 참조합니다.

## 12장 — 단위와 요구사항 할당

각 구현 단위가 어느 아키텍처 요소(`ARC-NNNN`)와 소프트웨어 요구사항(`SWR-NNNN`), 단위시험(SWE.4)에 연결되는지 개요로 기록합니다. 상세 추적성은 `traceability-and-integration.md`/`TPL-TRC-001`에서 관리합니다.

## 13장 — 구현 경계

자동 생성 코드, 외부 라이브러리, 플랫폼 종속부, 이번 상세설계에서 다루지 않는 범위를 명시합니다. 외부 라이브러리(특히 Python 패키지)를 사용한다면 `sbom-foss-compliance.md`로 이어집니다.
