# 시스템 테스트 설계기법

기본 기법(동등분할, 경계값분석 등)의 정의는 `tdd` 스킬의 `test-annotation.md`, `integration-testing` 스킬의 `test-design-techniques.md`와 동일한 개념입니다 — 여기서 다시 정의하지 않습니다. 이 문서는 시스템 테스트(SWE.6, 요구사항 명세서 기반 블랙박스 테스트)에서 어떻게 적용하는지와, 이 수준에서만 쓰는 기법(조합/페어와이즈, PICT 도구)만 다룹니다.

## 기법 선택 기준

| 기법 | 적용 대상 | 비고 |
| --- | --- | --- |
| 경계값분석(Boundary Value Analysis) | 검증기준에 수치·범위·임계값이 있는 요구사항 | 경계값 미만/경계값/경계값 초과를 각각 별도 케이스로 |
| 동등분할(Equivalence Partitioning) | 입력 도메인이 유효/무효 클래스로 나뉘는 요구사항 | 각 클래스의 대표값 |
| 전 조건 조합(Exhaustive Combination) | 관련 조건 수가 적어 전수 조합이 실행 가능한 범위 | 아래 PICT `/o:max` 옵션 |
| 페어와이즈(Pairwise) | 조건·값의 조합 수가 많아 전수 조합이 비현실적인 경우 | 아래 PICT 기본 옵션 — **시스템 테스트 수준 고유 기법** |
| 엣지 케이스(Edge Case) | 정상 범위의 극단, 동시성/타이밍 등 일반 분석 기법으로 포착 안 되는 조건 | |
| 경험 기반 테스트(오류 추정/탐색적) | 유사 시스템의 결함 이력, QA 경험 | ISO 29119/ISTQB 용어 체계 기준 |

요구사항 명세서(`ENG-SWE1-001`)의 요구사항 성격에 맞춰 위 기법 중에서 선택하고, `TPL-SWE6-001`의 `Technique` 열에 실제 적용한 기법을 명시합니다. 표에 없는 기법이 더 적합하다고 판단되면 지어내지 말고 근거를 들어 사용자에게 확인하세요.

## 조합 테스트 도구 — PICT

페어와이즈/전수 조합을 생성할 때는 오픈소스 도구 [PICT](https://github.com/microsoft/pict)를 사용합니다.

```bash
# 조건별 값 목록을 모델 파일(model.txt)로 정의한 뒤
pict model.txt                  # 페어와이즈(기본, 2-way) 조합 생성
pict model.txt /o:3             # 3-way 조합
pict model.txt /o:max           # 전 조건 조합(exhaustive) — 조건 수가 적을 때만
```

- 모델 파일에는 요구사항에서 도출한 조건과 그 값(동등분할/경계값분석으로 이미 좁힌 대표값)을 정의합니다 — PICT가 조합 폭발을 줄여줄 뿐, 값 자체를 대신 정해주지 않습니다.
- PICT 출력의 각 행을 `TPL-SWE6-001`의 케이스 하나로 변환하고, `Technique` 열에 "페어와이즈(PICT)" 또는 "전 조건 조합(PICT /o:max)"으로 기록합니다.
- 조건/값의 수가 적어 PICT 없이도 전수 조합이 몇 개 안 된다면, 도구 없이 직접 나열해도 됩니다 — 불필요하게 도구를 강제하지 않습니다.

## 통합 테스트/단위 테스트와의 관계

- **다른 점**: 이 스킬은 요구사항 명세서(`ENG-SWE1-001`)를 테스트 베이시스로 삼는 블랙박스 테스트입니다. `integration-testing`은 아키텍처 설계서(인터페이스/통합 순서)를 베이시스로 삼고, `tdd`는 상세설계 함수 계약을 베이시스로 삼습니다 — 세 스킬은 서로 다른 입력을 사용하므로 케이스를 중복 생성하지 않습니다.
- **커버리지**: 이 스킬은 요구사항 커버리지(모든 `SWR-NNNN`에 최소 1개 케이스)를 목표로 합니다. 함수/Call 커버리지(`integration-testing`) 또는 구문/분기 커버리지(`tdd`)와 혼동하지 마세요 — 이 스킬은 그 수치를 다루지 않습니다.
