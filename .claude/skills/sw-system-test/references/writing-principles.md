# 작성 원칙

- 의미 없이 테스트 커버리지 수치 달성만을 목적으로 하는 케이스는 생성하지 않습니다.
- 테스트의 예상 결과를 임의로 가정하지 않습니다. 요구사항 명세서(`ENG-SWE1-001`)에 예상 결과가 명확히 정의되어 있지 않으면, 이 스킬을 사용하는 에이전트(`sw-system-tester`)가 사용자에게 확인을 받아야 합니다.
- 요구사항 명세서에 실제로 기술된 내용에 근거해야 하며, 명세서에 없는 내용을 임의로 추측해 작성하지 않습니다.
- 프로젝트에서 정한 테스트 커버리지 목표(예: `CLAUDE.md`에 명시된 기준)를 준수합니다.
- 실행자가 그대로 재현할 수 있는, 실행 가능한 테스트 케이스만 작성합니다.
- 기법 선택이나 범위 설정이 판단하기 어려운 경우 임의로 결정하지 말고, `sw-system-tester`가 사용자 확인을 받습니다.
- 요구사항 원문에 없거나 원문보다 엄격한 판정기준을 확정했다면, `template-policy.md`의 `[확정: <일자>, 승인: <역할/성명>]` 관례로 `Expected Result` 셀에 근거를 남깁니다.
- 명세서에 직접적 근거는 없으나 QA 관점에서 추가를 제안하고 싶은 케이스는, `Test ID` 또는 케이스명 끝에 `(제안)`을 표시해 구분합니다.
- 사용한 테스트 설계 기법을 모든 케이스의 `Technique` 열에 명시합니다(`test-design-techniques.md`).
