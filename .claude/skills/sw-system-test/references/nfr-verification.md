# 비기능 요구사항의 시스템 테스트 케이스화

ISO/IEC 25010(SQuaRE) 품질 특성 정의와 전체 표는 `requirements-analysis` 스킬의 `nfr-iso25010.md`가 원본입니다 — 여기서 다시 나열하지 않습니다. 이 문서는 이미 정의된 비기능 요구사항(`SWR-NNNN`, `nfr-iso25010.md` 형식으로 작성됨: 특성/부특성, 정량적 기준, 검증방안)을 **실행 가능한 시스템 테스트 케이스로 구체화**하는 방법만 다룹니다.

## 절차

1. 대상 비기능 요구사항의 정량적 기준과 검증방안(기법: 시험/분석/검사/시연)을 `ENG-SWE1-001` 7장(비기능 및 환경 제약)에서 확인합니다.
2. 검증방안이 "시험(Test)"이면, 그 기준을 실제로 실행 가능한 `Stimulus`/`Expected Result`로 옮깁니다 — 요구사항의 정량적 기준(예: "200ms 이내")을 테스트의 통과/실패 판정 기준으로 그대로 사용합니다. 숫자를 임의로 바꾸지 않습니다.
3. 검증방안이 "분석/검사/시연"이면(예: 정적분석, 문서 검토), 시스템 테스트 케이스로 만들지 않습니다 — 이미 해당 활동(예: `tdd`의 정적분석, `aspice-auditor`의 리뷰)이 담당하는 영역이므로 중복 산출물을 만들지 않습니다.
4. `ID`는 `template-policy.md`의 `ST-NFR-<특성약어>-NNNN` 규칙과 특성약어표를 따릅니다.

## 실행 불가능한 케이스 금지

`requirements-analysis`의 `nfr-iso25010.md`가 이미 요구사항 단계에서 실행 불가능한 검증방안을 걸러내지만, 시스템 테스트 케이스로 구체화하는 이 단계에서도 다시 확인하세요.

- 실제로 접근 가능한 도구/환경이 없는 시나리오를 케이스로 만들지 않습니다.
- 판정 기준(수치/체크리스트)이 없는 케이스("충분히 빠르다")를 만들지 않습니다.
- 요구사항의 정량적 기준을 케이스 작성자가 임의로 더 엄격하게/느슨하게 바꾸지 않습니다 — 바꿔야 할 근거가 있다면 `template-policy.md`의 `[확정: ...]` 관례로 사용자 확인을 받은 뒤 기록합니다.

## 예시

| 요구사항(`SWR-0031`) | ISO 25010 특성 | 시스템 테스트 케이스 |
| --- | --- | --- |
| "요청 처리 응답시간은 200ms 이내여야 한다" | 성능 효율성 — 시간 반응성 | `ST-NFR-PERF-0004`: 부하 도구로 200회 요청, 95th percentile ≤ 200ms 판정 |
| "인증 5회 실패 시 계정을 잠근다" | 보안성 | `ST-NFR-SEC-0002`: 잘못된 인증정보로 5회 시도 후 6번째 시도가 거부되는지 확인 |
