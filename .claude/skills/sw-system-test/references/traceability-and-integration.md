# 양방향 추적성 (TPL-TRC-001 "SWE.6" 열 대응)

시스템 테스트는 추적 사슬의 마지막 칸을 채웁니다: 요구사항(`SWR-NNNN`) → ... → 통합시험(SWE.5) → **시스템 테스트(SWE.6)**. `requirements-analysis`의 `traceability.md`, `integration-testing`의 `traceability-and-integration.md`와 짝을 이룹니다 — 별도 매트릭스를 새로 만들지 않고 같은 산출물(`ENG-TRC-001`)을 갱신합니다.

## `ENG-TRC-001`에 기록할 값

| 열 | 기록할 값 |
| --- | --- |
| SWE.6 | 이 요구사항을 검증하는 시스템 테스트 케이스 ID(`ST-FUNC-NNNN`/`ST-NFR-<특성>-NNNN`, 여러 개면 나열) |
| Coverage | 이 요구사항까지 추적 사슬이 완성됐다면 "SWE.6까지 완료"로 갱신 |

## 유지 규칙

1. 시스템 테스트 케이스를 추가/변경/폐기할 때마다 같은 작업 내에서 `ENG-TRC-001`의 `SWE.6` 열을 함께 갱신합니다.
2. 요구사항(`SWR-NNNN`)이 존재하는데 대응하는 `ST-*` 케이스가 하나도 없으면 고아(orphan) 요구사항으로 간주하고 갭으로 보고합니다 — 요구사항 커버리지 100%가 이 스킬의 기본 목표입니다(`test-design-techniques.md`).
3. 요구사항이 변경되면, 그와 연결된 모든 시스템 테스트 케이스에 "재확인 필요" 표시를 남깁니다.
4. `ENG-SWE6-001`(명세), `ENG-SWE6-002`(결과), `ENG-TRC-001`(매트릭스) 세 산출물의 Test ID와 관계는 항상 일치해야 합니다.
5. `TPL-SWE6-001`의 `SW Req` 열 값과 `ENG-TRC-001`의 `SW Req` 열 값이 서로 다른 요구사항을 가리키면 안 됩니다 — 불일치를 발견하면 즉시 수정합니다.
