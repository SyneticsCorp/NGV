# ISO/IEC 25010 기반 비기능 요구사항(NFR) 작성

모든 비기능 요구사항은 ISO/IEC 25010의 품질 특성 중 하나 이상에 명시적으로 매핑하고, 정량적 기준과 실행 가능한 검증방안을 함께 제시합니다.

## 품질 특성 (개요)

| 특성 | 주요 부특성 예시 | 전형적인 NFR 예시 |
| --- | --- | --- |
| 기능 적합성(Functional Suitability) | 완전성, 정확성, 적절성 | 기능 결과의 정확도 허용 오차 |
| 성능 효율성(Performance Efficiency) | 시간 반응성, 자원 사용성, 용량 | 응답시간, CPU/메모리 사용량 상한, 최대 동시 처리량 |
| 호환성(Compatibility) | 공존성, 상호운용성 | 특정 인터페이스/프로토콜 표준 준수 |
| 사용성(Usability) | 인지 가능성, 조작성, 오류 방지, 접근성 | 특정 작업을 완료하는 데 필요한 조작 단계 수, 오조작 시 확인 절차 |
| 신뢰성(Reliability) | 성숙성, 가용성, 결함 허용성, 복구성 | 평균 고장 간격(MTBF), 장애 후 복구 시간(MTTR), 가용률 |
| 보안성(Security) | 기밀성, 무결성, 부인방지, 책임추적성, 인증성 | 인증 실패 처리, 권한 없는 접근 차단, 로그 무결성 |
| 유지보수성(Maintainability) | 모듈성, 재사용성, 분석성, 수정성, 시험성 | 순환복잡도 상한, 단위 테스트 커버리지 기준 |
| 이식성(Portability) | 적응성, 설치성, 대체성 | 지원 플랫폼/OS 목록, 설치 소요 시간 |

## 작성 형식

각 비기능 요구사항은 다음을 모두 포함해야 합니다.

1. **특성/부특성**: 위 표 기준 매핑 (복수 매핑 가능).
2. **요구사항 문장**: `clarity-and-consistency.md`의 EARS 패턴 준수.
3. **정량적 기준**: 측정 가능한 수치/조건. 수치화가 본질적으로 어려운 항목(예: 사용성 일부)은 체크리스트/척도 기반 기준(예: SUS 점수 하한, 특정 시나리오 완료율)으로 대체.
4. **검증방안**: 기법 + 합격 기준 + 필요 도구/환경.

## 검증방안 기법 (택 1 이상)

- **시험(Test)**: 실제 실행 환경/시뮬레이션에서 값을 측정 (예: 부하 테스트 도구로 응답시간 측정).
- **분석(Analysis)**: 계산/모델링/정적분석으로 판단 (예: 정적분석 도구로 순환복잡도 산출, WCET 분석).
- **검사(Inspection)**: 문서/코드/설정을 사람이 검토해 기준 충족 여부 판정 (예: 보안 설정 체크리스트 검토).
- **시연(Demonstration)**: 정해진 시나리오를 실제로 시연해 관찰 (예: 장애 주입 후 복구 동작 시연).

## 실행 가능성 판단 기준 — 아래에 해당하면 반드시 다시 작성

- **도구/환경이 실제로 존재하지 않음**: 프로젝트가 접근할 수 없는 장비, 존재하지 않는 테스트 환경, 확보 불가능한 데이터셋을 전제로 하는 검증방안.
- **판정 기준이 없음**: "충분히 안전해야 한다"처럼 합격/불합격을 가를 수치나 체크리스트가 없는 경우.
- **측정 대상에 접근 불가**: 소스가 없는 서드파티 바이너리에 대해 코드 커버리지 100%를 요구하는 등, 대상 자체에 필요한 접근 권한/가시성이 없는 경우.
- **비용/시간이 프로젝트 규모에 명백히 비현실적**: 예를 들어 소규모 내부 도구에 완전한 공식 정형 검증(formal verification)을 전제하는 경우 — 대상의 위험도/ASIL 수준에 맞는 검증 강도로 조정합니다(`iso26262-aspice-alignment.md` 참고).

위 문제가 발견되면, 검증 가능한 대체 기준(예: 전수 시험 대신 대표 시나리오 샘플링 + 신뢰구간 명시, 100% 커버리지 대신 리스크 기반 우선순위 커버리지)으로 다시 작성하고 그 사실을 산출물에 남깁니다.
