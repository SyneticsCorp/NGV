# 양방향 추적성 확보 방안

모든 요구사항은 상위(출처)와 하위(설계/구현/테스트 등, 존재하는 시점부터) 양방향으로 추적 가능해야 합니다. 이는 A-SPICE CL2 PA 2.2(작업 산출물 관리)의 핵심 근거이기도 합니다 — `aspice-auditor` 스킬의 체크리스트와 이 문서의 내용이 서로 대응해야 합니다.

## 추적 링크 종류

- **파생(derives)**: 상위 요구사항으로부터 이 요구사항이 도출됨 (예: 이해관계자 요구 → 시스템 요구사항).
- **만족(satisfies)**: 설계/구현 산출물이 이 요구사항을 만족함.
- **검증(verifies)**: 테스트 케이스/검증 활동이 이 요구사항을 검증함.
- **정제(refines)**: 상위 요구사항을 더 구체화함(계층 내 세분화).
- **포함(contains)**: 상위 요구사항이 여러 하위 요구사항을 포함함.

## 추적성 매트릭스 구조

프로젝트에 별도 도구(ALM 등)가 없다면 Markdown 표 기반 추적성 매트릭스를 산출물로 유지합니다.

```markdown
| 요구사항 ID | 출처(상위) | 파생/정제 하위 요구사항 | 설계 산출물(satisfies) | 테스트 케이스(verifies) | 상태 |
|---|---|---|---|---|---|
| REQ-SYS-FUNC-0012 | STAKE-0003 | REQ-SW-FUNC-0031 | DES-0007 | TC-0045 | 검증됨 |
```

- 링크 대상이 아직 존재하지 않는 단계(예: 아직 설계가 시작되지 않음)라면 해당 칸은 비워두고 "N/A(아직 해당 단계 아님)"로 표기합니다. 이를 "링크가 없다=문제"와 구분해야 합니다.
- 설계/테스트 등 하위 산출물이 이미 존재하는데도 링크가 비어 있다면 고아(orphan) 요구사항으로 표시하고 갭으로 보고합니다.
- 매트릭스의 ID는 `requirement-schema.md`(또는 지정 템플릿)의 ID와 정확히 일치해야 합니다. ID 불일치는 추적성 단절이므로 발견 즉시 수정합니다.

## 유지 규칙

1. 요구사항을 새로 추가/변경/폐기할 때마다 추적성 매트릭스를 같은 작업 내에서 함께 갱신합니다 — 나중으로 미루지 않습니다.
2. 하위 산출물(설계 문서, 테스트 케이스 등)을 작성/수정할 때 그 산출물이 어떤 요구사항 ID를 참조하는지 산출물 자체에도 명시하도록 안내합니다(양방향 확인 가능하게).
3. 요구사항이 변경되면 그 요구사항과 링크된 모든 하위 산출물에 "재확인 필요" 표시를 남깁니다(영향 분석).
4. 요구사항을 폐기할 때 ID를 삭제하지 않고 상태만 "폐기됨"으로 바꾸고, 관련 링크에도 폐기 사실을 반영합니다.
5. `uml-sysml-diagrams.md`의 Mermaid `requirementDiagram` 관계(derives/satisfies/verifies 등)와 이 매트릭스의 내용은 항상 일치해야 합니다 — 둘 중 하나만 갱신하고 끝내지 않습니다.
