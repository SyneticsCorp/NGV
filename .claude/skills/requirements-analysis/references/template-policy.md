# 템플릿 적용 정책

사용자는 요구사항 명세서에 사용할 지정 템플릿을 별도로 제공하기로 했으며, 아직 프로젝트에 전달되지 않았습니다(`CLAUDE.md`의 "지정된 템플릿을 이용한 산출물이 생성되어야 한다" 정책과 연결됨).

## 매 작업 시작 시 확인할 것

1. 프로젝트 내 템플릿 관련 경로가 있는지 확인합니다(예: `templates/`, `docs/templates/`, CLAUDE.md에 언급된 경로 등). Glob/Grep으로 `템플릿`, `template`, `양식` 등의 키워드를 가진 파일을 탐색하세요.
2. 템플릿을 찾았다면: 그 템플릿의 구조(섹션, 필드, 표 형식)를 그대로 따르되, `requirement-schema.md`에 정의된 필드가 템플릿에 없다면 누락된 필드로 보고하고 추가 여부를 사용자에게 확인하세요.
3. 템플릿을 찾지 못했다면: `requirement-schema.md`의 기본 스키마로 작성하고, 산출물 최상단에 다음과 같이 명시하세요.

   ```markdown
   > **주의:** 지정 템플릿이 아직 반영되지 않았습니다. 이 문서는 기본 스키마(requirement-schema.md)로 작성된 초안이며, 템플릿 제공 시 해당 형식으로 재구성해야 합니다.
   ```

## 템플릿이 나중에 제공되었을 때

- 기존에 기본 스키마로 작성된 요구사항 항목들을 새 템플릿 구조로 옮기되, 요구사항 ID와 추적 링크(`traceability.md` 참고)는 그대로 유지하세요 — ID나 링크가 바뀌면 기존 추적성이 끊어집니다.
- 템플릿이 요구하는 필드 중 기존 산출물에 없는 정보가 있다면, 지어내지 말고 "확인 필요"로 표시하세요.
