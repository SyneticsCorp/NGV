# ISO 26262 / A-SPICE 정렬 지침

이 문서는 요구사항 산출물이 두 표준의 기대사항과 어긋나지 않도록 하기 위한 실무 요약입니다. 공식 표준 문서(ISO 26262 각 파트, Automotive SPICE PAM/BPG)를 대체하지 않으며, 인증/계약상 엄밀함이 필요하면 공식 문서를 참조해야 합니다.

## ISO 26262 관점

- **안전 관련 여부 판단**: 요구사항이 안전목표(Safety Goal)나 그로부터 도출된 기능안전요구사항(FSR)/기술안전요구사항(TSR)과 연결되는지 확인합니다. 연결된다면 `requirement-schema.md`의 ASIL 필드를 채웁니다.
- **ASIL 상속**: 하위 요구사항의 ASIL은 원칙적으로 상위 요구사항의 ASIL을 상속합니다(분해/분할 시 별도 규칙 적용 가능 — 프로젝트의 안전 계획을 따릅니다). 상위-하위 간 ASIL이 근거 없이 달라지면 갭으로 기록합니다.
- **검증 강도와 ASIL의 관계**: ASIL이 높을수록 더 엄격한 검증 기법이 요구되는 경향이 있습니다(예: 높은 ASIL일수록 구조적 커버리지 기준이 엄격해짐). `nfr-iso25010.md`의 검증방안을 작성할 때 요구사항의 ASIL 수준에 맞는 강도인지 확인하고, 과도하거나 부족한 검증 강도를 지적합니다.
- **추적성**: 안전목표 → FSR → TSR → 설계 → 구현 → 테스트까지의 추적 사슬이 끊기지 않아야 합니다(`traceability.md`).

## A-SPICE 관점

- **SYS.1 이해관계자 요구 도출**: 요구사항의 "출처" 필드가 실제 이해관계자 요구 산출물을 가리켜야 합니다.
- **SYS.2 시스템 요구사항 분석 / SWE.1 소프트웨어 요구사항 분석**: 기능/비기능 요구사항이 속성(우선순위, 검증기준 등)을 갖추고, 상위 요구사항과 양방향 추적 가능해야 합니다 — 이 스킬의 스키마와 추적성 방안이 바로 이 기대사항을 채우기 위한 것입니다.
- **CL1 vs CL2**: 이 스킬은 요구사항이라는 산출물 자체(CL1 수준 기본 관행)를 만드는 데 집중합니다. 그 산출물의 생성 과정이 계획·모니터링되고 있는지(PA 2.1), 산출물 자체가 정의된 기준에 따라 식별·리뷰·형상관리되고 있는지(PA 2.2)는 CL2 영역이며, `aspice-auditor` 스킬/`aspice-cl2-auditor` 서브에이전트가 이어서 점검합니다.
- **일관성/명확성**: A-SPICE 심사에서 흔히 지적되는 사항이 "요구사항이 모호해 검증 불가" 또는 "요구사항 간 추적이 끊김"입니다. 이 스킬의 명확성(EARS)·일관성 체크와 추적성 방안은 이 지적을 예방하기 위한 것입니다.

## 이 스킬을 사용한 뒤 다음 단계

요구사항 산출물이 어느 정도 쌓이고 CL2 수준(계획/모니터링/형상관리 근거)까지 점검이 필요하면, `aspice-cl2-auditor` 서브에이전트를 사용해 이 산출물들을 감사하세요.
