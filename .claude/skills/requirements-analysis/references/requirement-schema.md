# 작업용 요구사항 스키마 (TPL-SWE1-001 대응)

TPL-SWE1-001은 장/절 구조와 서술형 작성 안내만 제공하고, 요구사항 항목을 담는 고정 표(컬럼)를 강제하지 않습니다. 이 문서는 각 장 안에서 요구사항을 일관되게 기술하기 위한 작업용 필드 스키마이며, 최종 산출물에서는 이 필드들을 TPL-SWE1-001의 해당 장 안에 표 또는 항목 목록 형태로 기술합니다.

## ID 체계

- 소프트웨어 요구사항: `SWR-<일련번호>` (예: `SWR-0012`). `OEM_Sample/OEM-SWR-001_OEM SW 요구사항 사양서.docx`가 하위 요구사항을 참조할 때 이미 이 접두사를 사용하고 있어, 우리 SWE1 산출물의 요구사항 ID를 이 접두사와 일치시켜야 상위(OEM) 요구사항과의 추적이 자연스럽게 연결됩니다.
- 프로젝트에 이미 다른 접두사가 쓰이고 있다면 새로 만들지 말고 기존 체계를 따르세요.
- 일련번호는 4자리, 0으로 채웁니다. ID는 재사용하지 않습니다(폐기되어도 "폐기됨" 상태로 남김).
- 외부 인터페이스 요구사항(6장)에는 `IF-<일련번호>`를 사용합니다(OEM 샘플의 `OEM-IF-xxx`와 대응하는 우리 쪽 접두사).

## 공통 필드

| 필드 | 설명 | 대응 장 |
| --- | --- | --- |
| ID | `SWR-NNNN` | 전체 |
| 설명 | EARS 패턴을 따르는 요구사항 문장 (`clarity-and-consistency.md`) | 4장 |
| 유형 | 기능(4.1) / 안전관련(4.2) / 비기능(7장) | 4, 7 |
| 분류/ASIL | 안전 관련이면 ISO 26262 ASIL(QM/A/B/C/D), 아니면 "N/A". OEM 샘플의 "분류" 열(예: "ASIL B 입력", "QM")과 동일한 의미로 사용 | 4.2 |
| 상태 | 초안 / 검토중 / 승인 / 변경됨 / 폐기됨 (2.1절 "식별 및 상태 규칙"에서 규칙을 함께 명시) | 2.1 |
| 우선순위 | 필수/권장/선택 등 (2.1절에서 규칙 정의, 3장에서 실제 값 기술) | 2.1, 3 |
| 출처 | 상위 요구사항(OEM 샘플 등) 또는 이해관계자 요구 ID | 11장(추적성) |
| 품질 판정 기준 충족 여부 | 2.2절 품질 판정 기준(명확성/일관성/검증가능성 등) 대비 자체 점검 결과 | 2.2 |

## 4장 — 기능 및 안전 관련 SW 요구사항

- **4.1 기능요구사항**: 공통 필드 + `관련 다이어그램`(Use Case ID 또는 `uml-sysml-diagrams.md` 다이어그램 참조) + `트리거/사전조건`, `예상 동작`(EARS 트리거-반응 쌍).
- **4.2 안전관련SW요구사항**: 공통 필드 + `ASIL` 필수 기재 + `관련 안전목표/FSR/TSR`(있다면) + `안전 메커니즘 연관성`(해당 요구사항이 어떤 오류 검출/처리와 관련 있는지, `architecture-design` 스킬의 안전 아키텍처 원칙과 연결).

## 5장 — 입력 데이터 사전

각 입력 데이터 항목: `이름`, `타입/단위/범위`, `출처(어느 인터페이스/요구사항에서 오는가)`, `유효성 조건`.

## 6장 — 외부 인터페이스 요구

| 필드 | 설명 |
| --- | --- |
| 인터페이스 ID | `IF-NNNN` |
| 방향 | 입력/출력/양방향 |
| 주요 데이터 | 전달되는 데이터 항목(5장 데이터 사전과 연결) |
| 단위/범위 | 값의 단위와 허용 범위 |
| 오류 처리 | 통신/데이터 오류 시 기대 동작 |

(OEM 샘플의 외부인터페이스 표 `인터페이스 ID │ 방향 │ 주요 데이터 │ 단위/범위 │ 오류 처리`와 동일한 필드 구성을 그대로 사용합니다.)

## 7장 — 비기능 및 환경 제약

`nfr-iso25010.md`의 필드(ISO 25010 특성/부특성, 정량적 기준, 검증방안)를 그대로 사용합니다.

## 8장 — 분석 결과와 가정

요구사항 도출 과정에서 사용한 가정, 미확정 사항, 분석 근거를 기록합니다. 지어낸 가정이 아니라 실제로 분석에 사용한 가정만 기록합니다.

## 9장 — 하향 할당 및 검증 계획

각 요구사항이 어느 하위 산출물(아키텍처 요소, 설계, 테스트)에 할당될 예정인지 개요 수준으로 기록하고, 상세 검증 계획(기법/합격기준)은 `nfr-iso25010.md`(비기능) 또는 SWE.4/5/6 산출물에서 구체화합니다.

## 10장 — 범위 밖 주장

명시적으로 이번 산출물의 범위에서 제외하는 항목과 그 사유를 기록합니다(요구사항으로 오인되지 않도록 분리).

## 11장 — 추적성

`traceability.md`(TPL-TRC-001 구조)를 그대로 참조하도록 안내 문구만 남기고, 실제 매트릭스는 별도 xlsx 산출물(`ENG-TRC-001`)에서 관리합니다.
