# 시험 설계기법 (ISO 26262 Part 6 기반, TPL-SWE5-001 §7 대응)

`TPL-SWE5-001` 7장은 "경계값, 동등분할, 의사결정표, 상태전이 등 기법의 선정 근거와 적용 대상"을 요구합니다. 이 문서는 ISO 26262 Part 6이 소프트웨어 통합시험에 대해 제시하는 기법들을 실무적으로 요약한 것으로, 공식 표준 문서 원문을 대체하지 않습니다.

## 시험 케이스 도출 기법 (테스트 대상 값을 어떻게 고를지)

| 기법 | 적용 대상 |
| --- | --- |
| 요구사항 기반 시험(Requirements-based test) | 모든 인터페이스/통합 항목에 기본으로 적용 — `SWR-NNNN`에서 직접 케이스를 도출 |
| 동등분할(Equivalence Partitioning) | 인터페이스 입력을 유효/무효 클래스로 나눠 대표값 시험 |
| 경계값분석(Boundary Value Analysis) | 인터페이스 데이터의 범위 경계(최소/최대, 경계±1) |
| 결정테이블 테스트(Decision Table Testing) | 여러 인터페이스/조건 조합에 따라 다른 통합 동작이 나올 때 |
| 상태전이 테스트(State Transition Testing) | 컴포넌트 간 상태 기반 상호작용(아키텍처 8장 상태 전이와 직결) |
| 오류추측(Error Guessing) | 경험상 흔한 통합 실수(타이밍, 순서 위반, 잘못된 형식) |

## 통합 수준 시험 방법 (무엇을 시험할지)

| 방법 | 적용 대상 |
| --- | --- |
| 요구사항 기반 시험 | 인터페이스가 요구사항/계약대로 동작하는지 |
| 오류 주입 시험(Fault Injection Test) | 오류 계약(`interface-and-integration.md`의 오류 계약)이 실제로 동작하는지 — 한쪽 컴포넌트가 실패/지연/잘못된 값을 보낼 때 상대 컴포넌트의 방어 동작을 검증. 안전 관련 인터페이스(ASIL 있는 요구사항과 연결된 경우)에는 특히 필수. |
| 자원 사용 평가(Resource Usage Evaluation) | 통합 후 타이밍/자원 제약(인터페이스의 시간 제약)이 유지되는지 |
| 백투백 시험(Back-to-back Test) | 참조 모델/이전 버전이 있을 때만 적용(해당 없으면 생략하고 그 사실을 명시) |

## 적용 절차

1. 대상 인터페이스(`IF-NNNN`)의 성격(데이터 검증형/상태기반/오류계약 중심 등)을 보고 위 표에서 기법을 선정합니다.
2. 선정 근거를 `ENG-SWE5-001` 7장에 기록합니다("이 인터페이스는 입력 범위 검증이 핵심이므로 경계값분석 적용" 등) — 임의로 기법 이름만 나열하지 않습니다.
3. `ENG-SWE5-002`의 `Technique` 열에 케이스별로 사용한 기법을 기입합니다. `tdd` 스킬의 `test-annotation.md`가 쓰는 기법 taxonomy와 이름을 통일해, 단위 테스트와 통합 테스트 간 기법 표기가 일관되게 합니다.
4. 하나의 인터페이스에 Positive(정상)와 Negative(오류/경계) 케이스가 모두 있는지 확인합니다 — `tdd` 스킬의 긍정/부정 케이스 원칙과 동일하게 적용합니다.

## 기법을 지어내지 않기

프로젝트 특성상 위 표에 없는 기법이 더 적합하다고 판단되면, 지어내지 말고 근거를 들어 별도로 제안하고 사용자 확인을 받으세요.
