# 테스트 베이시스: 아키텍처 인터페이스와 통합 순서

통합 테스트의 테스트 베이시스는 **아키텍처 설계서**입니다 — 요구사항 명세서가 아니라, `architecture-designer`가 만든 `ENG-SWE2-001`의 인터페이스 명세(6장)와 통합 전략(11장)입니다. 이 문서 없이는 통합시험을 설계하지 않습니다.

## 1. 인터페이스에서 시험 대상 도출

`ENG-SWE2-001` 6장(인터페이스 명세, `architecture-design`의 `interface-and-integration.md`)에서 각 인터페이스(`IF-NNNN`)의 다음 필드를 확인합니다.

- 제공자/사용자 컴포넌트
- 오퍼레이션(입력/출력, 단위/범위)
- 호출 조건(동기/비동기, 사전조건)
- 시간 제약
- 오류 계약

각 인터페이스마다 최소 하나 이상의 통합시험 케이스가 있어야 합니다. 인터페이스가 있는데 대응 케이스가 없으면 갭으로 보고합니다.

## 2. 통합 순서를 그대로 따른다

`ENG-SWE2-001` 11장(통합 전략)의 표(`순서 | 통합 단위 | 인터페이스 검증 | 스텁 또는 드라이버 | 회귀 범위`)가 통합시험 실행 순서입니다. `TPL-SWE5-001` 3장(통합 항목과 순서)에 이 순서를 그대로 옮겨 적습니다 — 새로 순서를 정하지 않습니다.

- 순서를 임의로 바꾸려면(예: 우선순위 재조정이 필요하다고 판단되면) 먼저 `architecture-designer`/사용자에게 근거와 함께 확인을 요청하세요. 통합 테스트 스킬이 독자적으로 순서를 결정하지 않습니다.
- 아직 통합되지 않은 의존 컴포넌트는 아키텍처의 "스텁 또는 드라이버" 계획대로 대체합니다.
- 통합 순서와 무관하게 인터페이스 케이스를 먼저 몰아서 실행하지 않습니다 — 순서대로 진행해야 "이 단계에서 새로 드러난 결함"을 정확히 격리할 수 있습니다(`TPL-SWE5-001` 2장 통합 원칙의 "실패 격리").

## 3. `Integration Item`/`Trace` 채우는 법 (TPL-SWE5-002)

| 열 | 채우는 값 |
| --- | --- |
| Integration Item | 이번 단계에서 통합되는 컴포넌트(들) — `ENG-SWE2-001` 11장의 "통합 단위" 값과 동일한 표기 사용 |
| Trace | 대상 인터페이스 ID(`IF-NNNN`, 하나 이상) + 관련 요구사항 ID(`SWR-NNNN`, 있으면) |

## 4. 아키텍처 산출물이 불완전할 때

- 인터페이스 명세가 비어 있거나 불명확하면: 지어내지 말고 `architecture-designer`로 보완을 요청하세요.
- 통합 순서가 없으면: 임의로 만들지 말고 동일하게 요청하세요.
- 아키텍처와 상세설계(`IU-NNNN`, 호출관계)가 서로 다른 내용을 말하고 있다면(불일치), 통합 테스트를 진행하기 전에 그 불일치를 먼저 보고하세요 — 어느 쪽이 맞는지 통합 테스트 스킬이 임의로 판단하지 않습니다.
